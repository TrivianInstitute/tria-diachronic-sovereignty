## Architectural maturity

The repository deliberately contains multiple maturity levels at once:

- **NORMATIVE** — governance commitments and constraints;
- **SPECIFICATION PRECURSOR / SPECIFIED** — structured representations intended to become implementable contracts;
- **EXPERIMENTAL** — reference implementation code and candidate mechanisms;
- **HYPOTHESIS / OPEN QUESTION** — claims requiring empirical work;
- **FAILURE MODE** — named diagnostic patterns that remain contestable.

A later version number must not be interpreted as evidence that all layers have reached the same level of validation.

## Change discipline

Future material revisions should record:

- what changed;
- why it changed;
- which claims or specifications are affected;
- whether prior behavior is superseded or merely supplemented;
- whether tests or examples changed with it;
- whether the change results from implementation experience, empirical evidence, critique, legal requirements, or conceptual revision.

Git commits preserve chronology. This record preserves architectural meaning.
