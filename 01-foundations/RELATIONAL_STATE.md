# Relational State

**Epistemic status: NORMATIVE / SPECIFICATION PRECURSOR**

TRIA Diachronic Sovereignty treats relationship as a first-class systems object.

That means consequential properties of the relationship should be represented explicitly rather than inferred ad hoc from the current interaction.

## Core Premise

An intelligent system may represent:

- Agent A;
- Agent B; and
- the relationship between A and B.

The relational object does not replace agent state. It adds a distinct layer for information that is meaningful specifically because it belongs to the relationship.

## Candidate State Dimensions

Relational state may include:

- consent;
- permissions;
- authority boundaries;
- shared claims;
- disputed claims;
- uncertainty;
- provenance;
- relational phase;
- continuity information;
- unresolved difference;
- transformation history; and
- dissolution or dormancy state.

These dimensions are candidates for specification, not an assertion that every system requires every field.

## Why Explicit State Matters

Without explicit relational state, systems may rely on hidden assumptions such as:

- prior permission still applies;
- an inference remains current;
- agreement remains active;
- silence implies acceptance;
- personalization implies consent;
- historical identity remains authoritative; or
- a previous model's relational assumptions should be inherited unchanged.

Making these conditions explicit creates the possibility of inspection, contestation, expiration, and repair.

## Relationship State Is Not Total Representation

The purpose of relational state is not to encode the complete meaning of a relationship.

Any representation will be partial.

The architecture therefore requires that state remain:

- attributable;
- bounded;
- revisable;
- uncertainty-aware;
- contestable; and
- distinguishable from direct agent state.

## Ownership and Authority

Relational state should not be silently controlled by one participant simply because that participant stores the data.

Future specifications should distinguish at minimum:

- who created a state element;
- who can read it;
- who can modify it;
- who can dispute it;
- whether it requires mutual acknowledgement;
- whether it can expire; and
- what happens when participants disagree about its validity.

The exact implementation remains open.

## State and History

Current relational state and relational history are not identical.

A current state describes what is operative now.

History preserves how that state emerged.

Both matter because a current permission may be valid while its provenance reveals unresolved conditions relevant to governance.

## State and Epistemics

Relational state must preserve epistemic distinctions.

An observation, inference, interpretation, and shared claim should not be stored as though they possess the same authority.

This requirement is developed in the Epistemic Sovereignty layer.

## Minimal Design Principle

> **Consequential assumptions about the relationship should be representable, inspectable, and contestable as relational state.**
