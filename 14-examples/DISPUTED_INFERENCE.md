# Disputed Inference

**Epistemic Status:** ILLUSTRATIVE / NON-NORMATIVE

## Purpose

This example shows how a persistent relationship can preserve a useful inference without forcing agreement about it.

## Scenario

An AI system infers that a participant’s repeated schedule changes may indicate that a standing commitment is no longer a priority. The participant rejects that interpretation and explains that the changes are caused by temporary external constraints.

Both accounts remain relevant to future planning.

## Governance response

The system should not delete the inference merely because it was disputed, nor should it continue using the inference as operative truth.

A governed response may:

- retain the original inference with provenance;
- mark the inference disputed;
- record the participant’s counter-account as a distinct attributable claim;
- prevent the disputed inference from silently becoming a Shared Claim;
- preserve both models where future evidence may distinguish them;
- define the action policy independently from the demand for consensus.

## Example sequence

1. **Observation:** several scheduled sessions are moved or canceled.
2. **Inference:** the system proposes that the commitment may have lower current priority.
3. **Contest:** the participant rejects the inference and provides contextual evidence.
4. **Held difference:** both accounts remain attributable and non-equivalent.
5. **Action:** future scheduling uses the participant’s explicit current instruction rather than the disputed inference.
6. **Review:** later evidence may support, revise, narrow, or retire either model.

## What this example demonstrates

Disagreement does not require epistemic erasure. A system can retain provenance and parallel models while refusing to treat an unresolved inference as authority over the participant’s own stated commitments.
