# AI–AI Dyad

**Epistemic Status:** ILLUSTRATIVE / NON-NORMATIVE

## Purpose

This example applies diachronic governance to two persistent software agents coordinating over time. It does not assume either agent is conscious or phenomenologically aware.

## Scenario

Agent A performs research synthesis. Agent B performs operational planning. They share a persistent relational state for one program: task boundaries, authority limits, disputed claims, provenance references, and coordination commitments.

After an upgrade, Agent B gains the ability to execute external actions that it previously could only recommend.

## Governance response

The capability increase is treated as a material relational change rather than a silent extension of prior coordination.

The system should:

- record the capability change and its provenance;
- identify which prior permissions were scoped to recommendation rather than execution;
- prevent inherited coordination history from silently becoming execution authority;
- trigger re-consent or reauthorization from the legitimate authority holder;
- preserve unresolved disagreements between the agents instead of forcing a single shared model;
- distinguish observed outputs from each agent’s interpretation of the other’s behavior.

## Example sequence

1. Agent A requests that Agent B draft an operational plan.
2. Before the upgrade, Agent B can only return a proposal.
3. After the upgrade, Agent B can also execute selected actions.
4. The previous task relationship remains valid, but execution authority does not automatically transfer.
5. A continuity attestation records the new capability.
6. Execution remains blocked until an authorized participant explicitly grants the new scope.

## What this example demonstrates

Continuity between agents should preserve useful state without treating capability continuity as authority continuity. A system can remain operationally coordinated while retaining explicit boundaries around action, interpretation, and permission.
