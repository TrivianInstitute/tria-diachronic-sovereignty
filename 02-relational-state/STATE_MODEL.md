# Relational State Model

TRIA Diachronic Sovereignty treats the relationship itself as a governed state-bearing object.

The purpose of the relational state model is not to record everything that happens between participants. It is to represent only those conditions that materially affect sovereignty, authority, consent, interpretation, continuity, contestability, or safe persistence.

> **Relational state is governance-relevant state, not total memory.**

## Design Objective

A relational-state representation should make it possible to answer questions such as:

- What permissions are currently active?
- What authority has been granted, denied, limited, or revoked?
- Which claims are observations, inferences, interpretations, or shared claims?
- Which claims are disputed?
- What uncertainty remains unresolved?
- What prior commitments still govern the present relationship?
- What changed, when, and under what authority?
- Does a current action depend on a stale or contested assumption?

## Minimum State Domains

A mature relational-state object should support, at minimum:

### Participants

Identities or identifiers for the participants whose relationship is being governed.

This field identifies participants for state coordination. It does not establish consciousness, personhood, moral status, or phenomenology.

### Consent

Current permissions and prohibitions, including whether a permission is:

- granted
- denied
- limited
- revoked
- expired
- ambiguous
- renewal-required

### Authority

The scope of actions each participant or system may take, including:

- decide
- access
- infer
- store
- disclose
- act
- delegate

### Epistemic State

The status of consequential relational claims.

At minimum:

`observation -> inference -> interpretation -> shared claim`

These categories must remain distinguishable.

### Disagreement

Disputed claims, unresolved interpretations, held differences, and explicit non-agreement.

Disagreement should remain representable without requiring immediate resolution.

### Uncertainty

Unknown, incomplete, stale, low-confidence, or insufficiently supported state.

### Provenance

The origin and history of consequential state, including:

- source
- timestamp
- actor
- prior state
- transition reason
- authorization basis

### Lifecycle

The present relational phase where relevant, such as:

- engage
- deepen
- stabilize
- rest
- dormant
- renew
- transform
- dissolve

Lifecycle state must not be interpreted as a requirement to progress toward deeper engagement.

## What Does Not Belong in Relational State by Default

The following should not be retained merely because they are available:

- complete conversation transcripts
- unnecessary biometric history
- unrestricted behavioral profiling
- unrelated personal information
- speculative psychological labels
- every preference ever expressed
- inferred identity attributes without governance relevance
- data retained only to increase engagement

A system should be able to justify why a retained field is necessary for relational governance.

## State Ownership

Relational state should not be treated as the unilateral property of one participant simply because that participant hosts the system.

Some fields may be participant-specific. Others describe the relationship itself.

A useful conceptual separation is:

```text
Agent A State
Agent B State
Relationship(A,B) State
```

This does not require equal technical control over infrastructure. It requires explicit recognition that relational claims and commitments may not belong exclusively to one party's interpretation.

## State Is Not Ground Truth

Relational state is a governed representation.

It may be:

- incomplete
- disputed
- stale
- wrong
- maliciously altered
- context-dependent

Every significant state representation should therefore remain compatible with provenance, uncertainty, contestability, and revision.

## State Minimization Principle

> **Store the minimum relational state necessary to preserve sovereignty, continuity, accountability, and contestability.**

More memory is not automatically better governance.

## Success Condition

The relational-state model succeeds when consequential assumptions about the relationship become visible enough to inspect, challenge, revise, or revoke without requiring total surveillance of the participants.
